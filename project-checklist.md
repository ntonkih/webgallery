# Web галерея частных фотографий — план проекта

## 1. Базовая информация
- **Название проекта:** Web галерея частных фотографий
- **Цель проекта:** Предоставить пользователю атмосферную онлайн-галерею, где легко находить и просматривать фотографии по категориям, узнавать историю снимков и взаимодействовать с автором через комментарии.

## 2. Ключевые пользовательские функции
1. **Загрузка фотографий с пропорциональным ресайзом**
   - Параметры по умолчанию: `1024×768` (Default)
   - Дополнительные пресеты: `1600×1200`, `800×600`
   - Предпросмотр и автоматическое сохранение EXIF-данных.
2. **Гибкая категоризация**
   - Иерархические категории, пользовательские теги, фильтры по автору/локации.
3. **Комментарии под фото**
   - Встроенный модераторский режим, поддержка Markdown и эмодзи.
4. **Карточка фотографии**
   - Описание, дата съемки/публикации, теги, место и автор.
5. **Админ-панель**
   - Авторизация, роли (админ/редактор), фильтрация, массовые операции, редактирование метаданных, удаление и архивирование.

## 3. Архитектура проекта
| Модуль        | Ответственность                                         | Технологии |
|---------------|----------------------------------------------------------|------------|
| Frontend SPA  | UI галереи, фильтры, просмотр и взаимодействие           | **React 18 + TypeScript**, Vite, Zustand (состояние), React Query, TailwindCSS, Framer Motion |
| Backend API   | REST/GraphQL, обработка загрузок, авторизация            | **NestJS (Node.js + TypeScript)**, Express адаптер, Sharp для изображений, JWT/Auth0 интеграция |
| База данных   | Хранение пользователей, категорий, метаданных, комментариев | **MySQL 5.6**, Prisma ORM |
| Админка       | UI для управления контентом, аналитика                   | **React 18 + TypeScript**, Ant Design, Vite, Recharts |
| Файловое хранилище | Масштабируемое хранение изображений, CDN             | Локальное файловое хранилище на сервере, подготовка к миграции на S3-совместимое облако |
| Инфраструктура| CI/CD, контейнеризация, мониторинг                        | Docker, docker-compose, GitHub Actions, Sentry, Nginx reverse proxy |

## 4. Оптимизация и масштабирование
- **UI/UX**: Мобильная адаптивность (mobile-first), тёмная/светлая темы, micro-interactions, доступность (WCAG 2.1 AA).
- **Оптимизация изображений**: Клиент — lazy loading, responsive images (`srcset`), blur-up placeholders; Сервер — Sharp (ресайз, webp/avif), кэширование, дедупликация.
- **Безопасность админки**: JWT + refresh токены, MFA опционально, IP allowlist, rate limiting, аудит логов.
- **Масштабирование**: Поддержка фильтрации по авторам/дате/тегам, лайки, избранное, поиск по полнотекстовым индексам MySQL.

## 6. План итераций (спринты по 2 недели)
1. **Спринт 0 — Подготовка**: требования, дизайн-направление, инфраструктура.
2. **Спринт 1 — Дизайн и каркас**: дизайн-система, прототипы, настройка фронтенд-проекта.
3. **Спринт 2 — Backend ядро**: сущности, MySQL схема, авторизация, базовая загрузка изображений.
4. **Спринт 3 — Пользовательская галерея**: листинг, фильтры, карточки, оптимизация изображений.
5. **Спринт 4 — Админ-панель**: управление контентом, модерация, продвинутые настройки ресайза.
6. **Спринт 5 — Интеграция и тестирование**: e2e, нагрузочные тесты, секьюрити аудит.
7. **Спринт 6 — Деплой и подготовка к расширению**: запуск продакшна, мониторинг, roadmap по лайкам/поиску.

## 7. Риски и контрольные точки
- **Риск:** медленная загрузка изображений → *Митигировать*: CDN/кеширование, lazy loading.
- **Риск:** перегруз админки функционалом → *Митигировать*: модульная архитектура, onboarding.
- **Риск:** безопасность токенов → *Митигировать*: ротация ключей, хранение secrets в Vault.

## 8. Метрики успеха
- Время загрузки LCP < 2.5s на 4G.
- Удержание пользователей: 60% возвращаются к просмотру новых альбомов в течение 30 дней.
- SLA админ-панели: 99.5% доступность.
